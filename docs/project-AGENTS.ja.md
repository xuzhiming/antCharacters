# この制作フォルダの入口

制作の共通知識は、開始依頼に示された**キットのルートAGENTS.md**を参照してください。必要環境、工程と確認地点、Skillsの選択、保存・再開、失敗時の対応はそこに集約しています。このファイルに工程説明を複製しません。

アプリからの依頼は、依頼文の `agent-session.mjs begin` が保存した出力のprojectを正本、directoryを制作フォルダとして扱います。キットのパスは開始依頼のスクリプトパス、またはローカルアプリのsession情報にあるappRootから確認できます。キットのルートAGENTS.mdと指定Skillを読んで、依頼された工程を進めてください。

候補選び直しでアプリが作成した分岐では、開始依頼に示された分岐側の正本を更新し、元の制作フォルダは保全します。このフォルダのproject.charakitを同じパスで更新し、元絵・採用候補・workのBlend・exportsの完成品を保全します。保存済みの工程名だけで検査済みと判断しません。完了・中断は開始依頼のcomplete・failで通知します。

揺れもの設定はavatar-spring-setupに従い、全対象の部位別計画をwork/character.blendへ保存します。rigのcompleteでそのBlendからVRMを生成し、部位別物理応答・MToon等を自動検査します。モデル情報が未登録でも検査済みVRMを動作確認へ表示します。モデル名・作者名・利用条件はアプリの「VRMを書き出す」で確認・登録し、形状・材質・物理を保持して正式保存します。FBXからの再読み込みで設定を失わないでください。見た目の評価や目視合格を完了条件にせず、修正はユーザーの明示依頼に従います。

利用者への説明・進捗・完了報告は今回の依頼で指定された言語に合わせます。英語は英語、韓国語は韓国語、簡体字中国語は簡体字で案内します。資料・Skillが日本語でも応答言語を変えません。ユーザーから明示的な変更があれば優先します。コマンド・パス・IDと利用者の素材名・メモは原文を保ちます。Tripoは日本語URLに固定せず、既存タブで依頼言語を選びます。未対応なら英語で開いて依頼言語で説明します。

## 表情制作expressionsの追加指示

expressions依頼はavatar-expression-authoringに従います。この工程では形を目標へ合わせるため、目視による比較と修正を反復します。上記のrig/finishの物理確認についての「目視合格を完了条件にしない」を、表情制作へ適用しません。原本を保持し、work/expression-authoringで必要な表情を制作して、scripts/expression-studio.pyの保存とregisterで同じ正本へ返します。既存VRMは表情付きとして案内しません。個人モデルの番号や移動量を汎用コードへ埋め込みません。

表情制作の完成条件は、お手本に沿って綺麗で可愛い仕上がりへ整ったことです。Computer Useで見ながら形を編集し、準備・カメラ・キー・撮影・保存は補助スクリプトやMCPで短く済ませます。管理手順・数値診断・保存成功を制作のゴールにしません。詳しくは同梱Skillを優先します。
