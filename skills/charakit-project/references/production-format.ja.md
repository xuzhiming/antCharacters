# 部位制作のデータ契約

## 保存と復元

部位制作を始めると`.charakit`はv6になります。旧v4・v5も読み込めます。`production`を持たないキットはv5のまま保存します。旧版アプリでv6は開けません。

新規制作は`production.version: 2`・`settings.maxTextures: 5`です。旧version 1・最大7のキットは変更せず読み込み・保存でき、既存返却物の組み立ても可能です。揺れ物だけの再分類は旧テクスチャを保持します。新しいテクスチャ用の再分類はversion 2へ移行し、旧分類のまま新しい`prepare`は実行しません。version 2は旧アプリでは開けません。

- `production.candidates.head/body`：最大4件ずつの元FBX、SHA-256、外部テクスチャ、normalization。採用IDは`selected`で別管理します。
- `segmented.head/body`：採用候補IDと結び付いたセグメンテーション後のFBXとnormalization。再テクスチャの基準です。元候補は維持します。
- `components`：不変の独立部品ID、元が頭か体か、意味の役割、頂点・面数、Blender座標の境界箱。正本FBXは`inventory`です。
- `textureGroups`：全成分を重複なく`hair/head/upper_body/lower_body/accessories`へ分類。頭・上半身・下半身は必須、存在しない髪・アクセサリーは省略。下半身は腰の衣装・スカートやズボン・脚・靴を含みます。各部位に`prepared`、`guides`、`references`、`returned`を保持します。
- `springGroups`：同じ部品IDを独立に分類。テクスチャ単位と一致する必要はありません。頭由来の揺れ物は髪だけです。
- 中間ファイルは`documents/production/`へ保存し、通常のアセットと同じSHA-256検証を行います。入力・中間の正本を使って、採用の変更・再分類・再生成を再開できます。
- 採用変更は分析以降をリセットします。テクスチャの構成変更は対応する書き出し・返却物を無効にします。揺れ物の分類変更だけならテクスチャを再利用できます。いずれも骨配置・ウェイトを古いまま引き継ぎません。

## メッシュ処理

揺れ物`kind: skirt`の成分も、テクスチャでは`lower_body`に含めます。統合FBX・着衣状態の参照画像から一枚の4Kテクスチャを作り、元の部品へUVを戻した後にスカート等を別メッシュにします。脚・靴・スカート単独のテクスチャ分類は作りません。装飾の帰属と分離できない場合の扱いは[5分類の境界](../../tripo-agent-workflow/references/retexture-images.md#テクスチャ用の5分類)を使います。

`scripts/production.py`をバックグラウンドBlenderで動かします。連結成分の全ポリゴンを分離し、基準モデルの頂点座標・面の頂点順・UVを保持します。採用後は `export-segmentation.py` で頭・体を三角化したGLBにし、Tripoの粗めセグメンテーション結果をFBXで登録してから分離・分類します。意味の判断や連結した面の切断は自動化していません。分離できない場合は、Blender Computer Useで試すか、Tripoで再生成・選び直すかをユーザーに確認します。

返却モデルには明示的な回転補正を適用し、部位全体の境界箱でサイズ・位置を合わせます。その後、近接頂点と面の対応を全件検査し、**基準メッシュの座標と面構成を変えずにUV・材質を移します**。UV継ぎ目の重複頂点は対応できます。基準からの面構成変更・再メッシュ・欠落面・一致しない形・重複面などは拒否し、入力キットを維持します。対称形状から前後や左右の回転を推測しません。

最終FBXは従来の`body/head_neutral/hair`へまとめます。頭と髪は同じnormalizationで元の相対位置を保ちます。体の通常部分は`Body`、衣装の揺れ物は個別オブジェクトにし、材質はグループをまたいで共有できます。`weightTransferPlan`へ体のSHAと揺れ物の名前を保存し、既存のウェイト転送へつなげます。

リギングは頭と体だけをTripoへ送り、既存の`import-bones.mjs`で骨配置のみをサイズ補正して読み込みます。再テクスチャとリギングでは返却物の利用範囲が異なります。
