# 画像の保存と返却

## 初回の8枚

頭（顔と髪を一体に含む）・衣装込みの体について、正面・左・右・背面をPNGで1枚ずつ作ります。ZIP内は`head/front.png`、`head/left.png`、`body/back.png`など、`head`と`body`の2フォルダ×4方向です。髪単独の画像や空のダミー画像を追加しません。

実際に使ったプロンプトを各PNGの`AvatarKit`メタデータへ入れます。元絵などの参照入力はユーザー側で保持し、ZIPには追加コピーしません。第三者の観察用画像は生成への画像入力にも使いません。採用理由、修正履歴、HTML閲覧ページ、説明文書は納品しません。

`node scripts/package-images.mjs images.json images.zip`で8枚をまとめます。`images.json`は次の形式で、相対パスは設定ファイルを基準にします。例の1行だけで実行せず、8スロットをすべて指定します。

```json
{"images":[{"slot":"head/front","file":"head-front.png","prompt":"実際に使ったプロンプト"}]}
```

ZIPのslot名には`/neutral`を付けません。アプリが読み込む際に`head/front/neutral`等へ対応させます。既存のファイル形式、プロンプト保存、ハッシュ検査はそのまま使います。画像とZIPを返し、アプリの「ZIPを読み込む」で選ぶよう案内します。ユーザーに個別登録や手動展開を求めません。

アプリのZIP読み込みはPNG・JPEG・WebPの混在にも対応します。拡張子は`.png`・`.jpg`・`.jpeg`・`.webp`です。プロンプトの埋め込み対象はPNGです。`references/`は読み込み時に無視します。自作見本のキット同梱を明示的に頼まれた場合は別工程で扱い、制作画像だけのZIPへ自動追加しません。

## バランス調整用の三面図

一括images依頼では部位画像8枚の制作・登録後に[character-three-views](../../character-three-views/SKILL.md)を使います。元絵の1枚絵を部位制作のデザイン基準に保ち、三面図は最後にバランス用として作ります。登録とZIPの`threeViews`設定は[専用の返却形式](../../character-three-views/references/delivery.md)に従います。三面図は部位スロットへ含めず、アプリで自動読み込みします。

## 旧3分割の互換性

既存の`head`・`hair`・`body`の12枚も読み込み・書き出しできます。`package-images.mjs`も完全な旧12枚セットを受け付けます。新規は8枚を標準とし、8枚と完全な旧12枚以外の不完全セットは初回パッケージとして渡しません。

髪単独の旧画像があるプロジェクトでは、画像画面に旧髪欄を残します。既存の頭画像を自動で髪込みと解釈したり、旧髪画像を消したりしません。画像の2分割化だけで3Dモデルのロール・配置・メッシュを移行したとは扱いません。

## キット内の1枚を修正

依頼文のslot、画像パス、ハッシュで対象を確認します。ユーザーが指定した変更だけを行い、他の画像・モデル・配置には触れません。実プロンプトを保存し、`node scripts/update-images.mjs changes.json project.charakit`で返します。対象スロットの過去画像と、そこへ向いた旧参照リンクは保持しません。旧設定の`references`や`key`は受け付けますが、参照ファイルは読み込み・複製しません。

```json
{"input":"original.charakit","images":[{"slot":"head/front/neutral","file":"revised.png","expectedSha256":"依頼文にある64文字のSHA-256","prompt":"実際に使った修正プロンプト"}]}
```

こちらのslotには`/neutral`が必要です。旧`hair/*/neutral`の指定修正も可能ですが、その依頼から2分割への変換を推測しません。旧表情・瞳データは残し、現在の制作対象にはしません。画像を変更しただけで3Dモデルへ反映済みとは扱いません。

## ローカル連携での保存

agent-session.mjs begin（旧形式は start）を含む依頼では、8枚制作も1枚修正も scripts/update-images.mjs で入力と同じ正本へ登録します。実プロンプトを保存し、completeでアプリへ通知します。この経路でZIPの手動登録、キット添付、別名キットの作成を要求しません。上記ZIP納品は独立したファイル納品の依頼に適用します。
