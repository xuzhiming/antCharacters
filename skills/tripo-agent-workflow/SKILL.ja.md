# Tripoを操作する

ユーザーが依頼した工程を実行します。アプリの依頼文とstartが保存した正本キットを照合し、[charakit-project](../charakit-project/SKILL.md)で検査・展開してください。`production`は制作途中の正本です。候補FBX、独立部品、テクスチャ用グループと揺れ物用グループを同じ意味として扱いません。

Tripo操作は利用可能なComputer Useまたは接続済みChromeのブラウザー操作を使います。操作ツールのスキルと[ブラウザの選択と再利用](../../docs/browser-use.md)を先に読み、ユーザーの既存ブラウザ・ログイン済みタブを使います。対象タブがなければ同じウィンドウ・プロファイルに追加し、ブラウザ自体が開いていないことを確認した場合だけ新しく起動します。接続がなければユーザーに接続・ログインを依頼し、Codex内ブラウザや別の自動操作用セッションへ自動で切り替えません。利用規約の回避、非公開APIの推測、ブラウザープロファイルや認証情報の抽出は行いません。ファイル処理は同梱スクリプトで進めます。

UIは更新されるため、[画面で確認する設定](references/tripo-ui.md)は探索の手掛かりです。毎回、現在の画面と実際の選択値を確認します。既に依頼された生成・Smart UV・テクスチャ・リギングの通常操作を、工程ごとに再承認待ちへ戻しません。追加の購入やプラン変更が必要な場合は、その操作をユーザーに確認します。

すべてのStudio出力は[tripo-studio-download](../tripo-studio-download/SKILL.md)で取得します。通常のExportをクリックし、ブラウザの保存フォルダの実ファイルを確認して制作フォルダへ受け取ります。ダウンロードイベントの待機・保存ヘルパーは併用しません。拒否・未完了・別モデルを成功扱いせず、復旧と実ファイル検査も同スキルに従います。

## 候補を生成する

1. キット内で採用中の `head/{front,left,right,back}/neutral` と `body/{front,left,right,back}/neutral` を確認します。頭には髪をすべて含め、体は必ずTポーズです。画像不足・Aポーズ・明らかな方向不整合は画像工程へ戻します。勝手に単一画像生成へ落としません。
2. Tripoのマルチビューに1部位の4方向を渡します。**Smart Mesh P2.0、四角面、25,000、生成数4**を確認して、頭・体それぞれ生成します。バッチ画像入力とマルチビューを取り違えません。
3. [tripo-studio-download](../tripo-studio-download/SKILL.md)で候補をすべてFBXとして取得・検査し、必要なテクスチャを一緒に保存します。[CLIの契約](references/commands.md)の`candidates`で登録します。取得記録のモデルID・用途・SHA256と元画像の対応を残します。
4. 同じ正本を更新してcompleteを実行し、ユーザーがアプリで頭・体を決定するところで止めます。エージェントが採用済みに書き換えません。

## セグメンテーションから組み立てまでの一括依頼

materialsの依頼は分類や分離の途中で止めず、組み立て完了まで進めます。最初に `scripts/export-segmentation.py` をBlenderで実行し、採用した頭・体をGLB（三角面）で書き出します。Tripoへ再アップロードして粗めのセグメンテーションを実行します。[tripo-studio-download](../tripo-studio-download/SKILL.md)で結果をFBXとして取得・検査し、tripo-project.mjs の segmented で登録します。元候補と採用IDを残し、セグメンテーション後を新しい基準にします。

## 独立した部品を分類する

1. 両候補が採用済みなら`analyze`を実行します。アプリの「採用モデルを分離する」も同じ処理です。頂点で連結した部品を列挙し、登録された基準モデルの面構成を保って分離します。
2. `components.fbx`をアプリまたは作業用Blenderで表示し、正面・側面・背面と部品単独表示を照合します。**意味の分類はエージェントが目視で行います**。大きさ・位置・連結数だけで髪や肌を決めません。
3. 各部品に`head`・`hair`・`body`の役割を付けます。髪は頭と同じ座標系です。テクスチャは[5分類の境界](references/retexture-images.md#テクスチャ用の5分類)に従い、`hair`・`head`・`upper_body`・`lower_body`・`accessories`へ全成分を重複なく割り当てます。**下半身は腰の衣装・スカート・脚・靴を一組にします。脚・靴・スカートだけのテクスチャ分類は作りません。** 初期8枚の頭／体の分け方は変更しません。
4. 揺れ物グループは同じ部品IDを別に指定します。**スカートと脚を揺れ物のために分離していても、テクスチャでは同じ下半身です。** スカート・リボン・髪束等の揺れ方に必要なまとまりを指定し、テクスチャの5分類や枚数に合わせません。大きなリボンをアクセサリーへ分類しても、揺らすかどうかは別に決めます。対象なしは確認のうえ空配列にします。
5. 分離したい境界が連結面の中にある場合は、画像を示して次の選択肢をユーザーに確認します。**BlenderをComputer Useで操作して分離を試す（不安定・トークン多め）／Tripoで再生成または候補を選び直す（比較的安定）**。勝手な切断・省略は行いません。手作業で形状を変更した場合は、新しい候補として登録し直し、分析以降をやり直します。

## Smart UVと再テクスチャ

1. 分類を登録し`prepare`で部位FBXと正面・背面のワイヤーガイドを作ります。各テクスチャグループ内の部品を1つのメッシュオブジェクトに統合して書き出します。離れた部品の頂点は溶接せず、基準の部品分離と揺れ物グループは保持します。書き出しはY-upのベイク済みFBXです。アップロードの初期補正は0°、Tripoの実プレビューで顔の前方向・上下を確認します。必要な補正を記録し、90°を重ね掛けしません。
2. [再テクスチャ素材](references/retexture-images.md)に従い、ガイドで形を合わせ、採用マルチビューで塗りを合わせた**部位ごとの正面・背面PNG**を生成します。`references`でキットへ登録します。
3. Tripoへ1グループずつアップロードし、**Smart UVを先に実行**、続いて画像参照でテクスチャを再生成します。解像度は**4K固定**です。Remove Lightingは`production.settings.removeLighting`に従い、初期値はOFFです。再メッシュやポリゴン削減をかけません。
4. [tripo-studio-download](../tripo-studio-download/SKILL.md)で再生成済みFBXを取得・検査し、各グループIDに対応させ`returns`で登録します。出力ファイルの取り違えをプレビューと形で確認します。`assemble`は基準部位の頂点・面へUVと材質を移し、Tripoの位置・大きさ変更を取り除き、`scripts/mtoon-export.py` で全メッシュのマテリアルへMToonを適用して `assembly.blend` を保存します。頭身調整以降のアプリ表示もMToonです。後のFBX読み込みではMToonを再適用し、作業用Blendと最終VRMまで維持します。明示的な軸補正が必要なら`rotation`（Blender XYZ度）を指定します。左右対称の形から向きを推測して補正しません。
5. 復元が失敗した場合は、出力の軸・基準部位・面構成・テクスチャを調べます。メッシュの対応不成立をサイズ補正成功として扱いません。修復困難ならユーザーへ該当部位を示します。組み立て済みキットを返し、頭と体の大きさ・位置はアプリでユーザーが合わせます。

## Tripoのリギング

ユーザーが配置を終えて依頼したら、頭＋体を `scripts/export-rig.py` またはアプリの書き出しから取得し、Tripoでリギングを実行します。髪は含めず、衣装・分離済み揺れ物は含めます。ボーン位置のプレビューを確認し、[tripo-studio-download](../tripo-studio-download/SKILL.md)でFBXを取得・検査します。

`node scripts/import-bones.mjs INPUT.charakit RETURNED.fbx INPUT.charakit`で、元サイズに戻した骨配置だけを保存します。Tripoのリグ付きメッシュやウェイトで元のテクスチャ済み部位を置き換えません。rigの一括依頼では scripts/run-local-job.mjs でウェイト転送→変形確認→揺れ物設定まで続け、確認用FBXをphase=springsで同じ正本へ登録してcompleteを実行します。VRMの正式出力はユーザーの動作確認後です。揺れ物の分類結果と実際の物理設定完了を区別します。
