# マーカーからVRM HumanoidとTポーズを作る（実験版）

同梱の `../scripts/humanoid_setup.py` をBlender内で使います。担当範囲は、VRM Humanoidの新規作成、元姿勢への骨配置、仮ウェイト、腕のTポーズ補正、メッシュと骨のレスト化です。細かなウェイト、骨のロール、眼ボーンの中心、揺れもの、VRMの最終品質は画面で検証・調整します。

機械的な段階処理はMCP・スクリプトで実行します。形状の観察・選択・調整にはComputer Useを使います。標準の新規制作では通常顔と固定された目を扱い、表情・眼の下処理は行いません。

## 入力と保全

- Blender 5.2と公式VRM Add-onを使用します。インストール済みの `bl_ext.blender_org.vrm` を有効化し、Add VRM HumanoidとVRM 1.0の骨割り当てを使います。アドオンをダウンロードしたり既存リグを上書きしたりしません。
- `.charakit` を同梱の `charakit-project` で検査・展開し、その `project.json` を指定します。座標はメートル、Z上・正面-Y・本人左+Xです。モデルをBlenderで配置し直した場合は、マーカーとの整合を確認してから実行します。normalizationやplacementsはマーカーへ再適用しません。
- 初期対象はリグのない体・衣装です。処理対象の**メッシュオブジェクト名を明示**し、コンテナEmptyは指定しません。頭・髪などは必要に応じて固定追従先を明示します。使用しない原本や別版まで選びません。
- 作業用コレクション `CharaKit_Rig_Work` にオブジェクト・メッシュをコピーして処理します。元オブジェクトを編集しません。元モデルとコピーが重なって見えるため、UIで作業用コレクションを表示対象にして確認します。各段階で出力フォルダに一意な名前の `.blend` とJSONレポートを保存します。現在のファイルへの上書き保存はしません。
- 既存リグ・オブジェクトアニメーション・制約、追加の有効なモディファイアがある対象には、そのまま適用しません。頂点構造を変えるモディファイアなどを自動で消して続行せず、作業コピーで別途整理します。

## 実行方法

BlenderのScripting画面でスクリプトを読み込みます。次のように同梱スクリプトをロードし、**1段階ずつ** `run` を呼び出します。パスとオブジェクト名は実データのものに置き換えます。この段階ごとの画面確認は通常の制作判断であり、毎回ユーザーの承認を待つ手順ではありません。

```python
import runpy
setup = runpy.run_path('/absolute/path/to/kit/skills/tripo-character-setup/scripts/humanoid_setup.py')
report = setup['run']({
    'stage': 'create',
    'project_json': '/absolute/path/to/extracted/project.json',
    'output_dir': '/absolute/path/to/production/work/humanoid',
    'deform_objects': ['BodyMesh', 'SleeveMesh'],
    'rigid_objects': {'ExpressionHeadMesh': 'head', 'HairMesh': 'head'},
})
print(report['rig'])
```

`deform_objects` は自動ウェイト対象、`rigid_objects` は指定したVRM human boneへ100%固定する対象です。瞳を後で眼ボーンへ割り当てる場合も、実際の対象名を調べて指定してください。眼ボーンの推定位置は完成位置ではありません。

生成したリグ名（例：`CharaKit_Humanoid`、重複時は連番）を、以下の `rig` に指定します。各段階を保存したファイルから再開するときも、そのリグ名を使います。

```python
setup['run']({'stage': 'bind', 'rig': 'CharaKit_Humanoid'})
# 画面で仮ウェイトを確認してから次を実行
setup['run']({'stage': 'preview', 'rig': 'CharaKit_Humanoid'})
# Tポーズの肩・脇・袖・手を多方向から確認、必要ならUIで補修してから確定
setup['run']({'stage': 'commit', 'rig': 'CharaKit_Humanoid'})
```

JSONファイルを用いる場合は、Blender内の実行環境に `CONFIG_PATH` を設定してスクリプトを実行できます。バックグラウンド検証では `blender --background input.blend --python humanoid_setup.py -- config.json` を使います。制作中の別Blenderへ接続する処理はありません。

## 1. create：元の姿勢へ骨を配置

Aポーズや少し下がった腕も、まず元のマーカー通りに配置します。肩マーカーは上腕の始点、肘は上腕の終点と前腕の始点、手首は前腕の終点と手の始点です。手の中心は手ボーンの方向・長さの目安です。鎖骨の始点は胸と首から推定します。

骨名の文字列を独自推測せず、VRM Add-onのHumanoid割り当てから対象ボーンを求めます。指マーカーが揃う指はその位置を使い、不足する指・眼・頭頂などはテンプレートを親ボーンに合わせて配置します。ロールと推定部分はUIで確認します。マーカーの同一点・ゼロ長ボーンはエラーにします。

## 2. bind：仮ウェイト

体・衣装にはBlenderの自動ウェイトを使います。固定対象は指定骨へ100%割り当てます。Armatureは線形変形、頂点グループ方式です。未ウェイト頂点があれば止めます。失敗後は出力された `before-bind` のファイルへ戻して対象構造を見直します。途中状態へ同じbindを重ねません。

自動ウェイトに数値が入ることは、肩や袖が自然に変形する保証ではありません。肩・脇・腕を上げるために必要な補修は**レスト化前**に行います。潰れた形を基準形状に焼き込んでから直す流れにはしません。

## 3. preview：腕をTポーズへ

上腕・前腕・手を左右別に計算し、本人左+X・右-Xへ向けます。固定角度や左右対称の仮定を使わず、骨の長さを保持します。腕が既に水平なら補正量はほぼ0です。脚・頭・眼・指の姿勢を一括リセットしません。手の向き・ロールは多方向から確認します。

previewは同じ入力から再計算でき、二重に回転しません。ただし上腕・前腕・手のポーズを再計算するため、UIでそれらを修正した後は、再previewせず確認してcommitへ進めます。骨のロールの修正は必要に応じてcreate後の段階で行います。

## 4. commit：メッシュと骨を同時にレスト化

確定直前の復帰版を保存し、対象メッシュのTポーズ時の座標を計算してから書き込みます。シェイプキーがある場合はBasisと各キーへ同じスキニング変換を適用し、キーを削除せず名前・相対キー・ドライバーを保持します。その後、現在の骨の姿勢をレストポーズに適用します。Armatureモディファイアとウェイトを残し、二重変形がないか各キーの座標を確認します。

この実験版は単一のArmature、線形スキニング、単位ボーンスケールを対象にしています。他の有効モディファイア、制約、アニメーション、非単位ボーンスケール、マスク付きArmature、未列挙の従属メッシュを検出した場合は拒否します。対象外を黙って除外して一部だけレスト化しません。作業中に新しいバインド対象を増やした場合は、構成を整理してから再開します。

完了条件はポーズをリセットしてもTポーズのままで、確定前後の見た目が変わらず、既存シェイプキーと首周りの変形が保たれることです。commit済みのリグへ再commitはできません。失敗した場合は `before-rest-commit` のファイルへ戻します。

元のマーカーは補正前の姿勢の記録として保持します。Tポーズ化後のリグへ元マーカーを再適用しません。元の.charakitやFBXを自動更新せず、採用したBlendから必要に応じて既存の受け渡し工程で書き出します。
