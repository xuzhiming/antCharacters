# 揺れ物の推定と転送の準備

アプリのフォルダを基準に`skills/charakit-project/SKILL.md`と[共通ルール](../charakit-project/references/common.md)を読みます。

ローカルのrig一括依頼では、既に有効なweightTransferPlanがあれば再分類せず、骨配置取得後に scripts/run-local-job.mjs の transfer-weights を実行し、揺れ物設定と完成VRMの自動検査へ続けます。見た目の合格はエージェントの完了条件にせず、ユーザーの動作確認へ委ねます。以下の分離後終了は、単独の事前分離依頼に適用します。

標準の担当はAstraが揺れ物の判断・分離・命名、アプリが素体合わせと転送です。骨配置がまだなくても判断を始めます。操作手順は[揺れ物の事前分離](references/spring-review.md)です。

- スカート・リボン・ストラップ等を目視し、独立した部品を意味のある単位でまとめます。残りは`Body`、揺れ物は`Skirt`、`BackRibbon_Left`等の分かる名前にします。
- 一体化して分離できない部分は、該当箇所を囲う・矢印を付けたスクリーンショットを示し、「ここは服とつながっています。この部分を揺らさず進めますか？」等の平易な言葉で判断を求めます。回答までその部分を切断・省略・対象なし扱いにしません。
- 分離した実オブジェクトと名前・種類・分離済み状態を.charakitへ保存します。対象がなければ空の一覧を明示します。
- 更新済みキットを返し、アプリで開き直す案内をしたら依頼完了です。Tripo操作・素体合わせ・転送・揺れ設定へ勝手に進みません。
- Tripoへ揺れ物を含めるかはユーザーの検証待ちです。現在は分離後も衣装を含む見た目全体を送り、髪だけ外します。衣装の下に体がないケースを勝手に補完しません。

アプリの自動転送は同梱の抽出済み素体（またはローカル設定の代替素体）を使い、分離した揺れ物を外して体だけに転送します。揺れ物は仮固定で保持し、仕上げSkillへ引き継ぎます。計算成功を見た目の合格にしません。

テクスチャ確定・組み立て時に適用したMToonを維持します。FBXから原本メッシュを読み込むときは `scripts/mtoon-export.py` の `apply_mtoon(meshes)` を再適用し、テクスチャ・UV・透明度を保持して、準備・素体合わせ・転送後のBlendを保存します。`from_guide.py` の自動経路は読み込み直後にこの処理を行います。

マーカー経路や既存リグで手動転送が必要なときだけ[手動転送](references/manual-transfer.md)を読みます。
