# Tripo StudioのFBXを受け取る

取得は **通常Export → ブラウザの保存フォルダ → 実ファイル確認 → 制作フォルダへコピー** で進めます。追加のダウンロード用拡張・Tripo APIキー・DCC Bridgeは不要です。モデル生成や正本への登録は呼び出し元の工程に戻して行います。

## Export前の準備

1. 利用中のブラウザ操作ツールのスキルと[ブラウザの選択と再利用](../../docs/browser-use.md)に従い、ユーザーの既存ブラウザ・ウィンドウ・プロファイルを使います。現在のStudio画面で対象モデルID・プレビュー・工程を照合します。タブを誰が開いたかを取得可否の条件にはしません。
2. ブラウザが実際に保存するフォルダを確認します。既定のDownloadsを推測だけで採用せず、変更された保存先や「保存先を毎回確認する」設定なら現在の保存画面も確認します。ブラウザ操作とファイル操作は同じPCで実行します。別PC・クラウドでローカルのDownloadsを読めない場合は、接続不足を報告します。
3. アプリのbeginで確認した制作フォルダ内の既存 `work/` を使い、下記のprepareを実行します。モデルID、用途、開始時刻を記録し、過去のファイルと衝突しない固有名を発行します。

```text
node "<キット>/skills/tripo-studio-download/scripts/receive.mjs" prepare --work "<制作フォルダ>/work" --downloads "<ブラウザの保存フォルダ>" --model "<StudioモデルID>" --label "head-candidate-1"
```

`prepared` の出力から `job`・`exportName`・`source` を控えます。body、セグメンテーション、再テクスチャのグループ、rigも用途が分かるlabelにします。ファイル名はこの操作で発行したものを使います。

## 通常のExport操作

現在の画面でExportを開き、**FBX・Blenderプリセット**と必要なテクスチャの設定を確認します。名前欄に `exportName`（拡張子なし）を入れ、画面のExportボタンを通常クリックします。設定と対象モデルの対応をworkへ記録します。ブラウザ標準の保存画面が出た場合も、操作可能なUIで同じ保存先・固有名を指定します。

**Tripo StudioのExportには `waitForEvent('download')`、`downloadMedia`、ダウンロードイベントの待機・捕捉・保存ラッパーを併用しません。** ブラウザ標準の保存に任せ、以下のファイル確認へ進みます。通常のクリックを別のダウンロードヘルパーで包み直しません。この制約はStudioの取得経路に限ります。

## 実ファイルの確認と受け取り

```text
node "<キット>/skills/tripo-studio-download/scripts/receive.mjs" receive --job "<prepareが返したjob>" --timeout-ms 20000
```

- `pending`：指定ファイルが未着、`.crdownload`が存在、またはサイズ・更新時刻が安定していません。ブラウザの現在の状態を確認し、Exportを押し直さず、同じjobのreceiveを再実行します。通常は全体で120秒までを目安にし、処理中の表示が続く場合は進捗を伝えます。
- `received`：新しいFBXの形式ヘッダー、安定したサイズ、コピー前後のSHA256が一致しました。`path`に制作フォルダ内のコピーがあります。元のDownloadsのファイルと既存の成果物は保持します。再実行は保存済みコピーのハッシュを再確認します。
- エラー：取得成功として登録しません。既存ファイル、別名への自動連番、HTML、ZIP、別モデル、対象外の保存先を黙って代用しません。

ヘッダー検査はメッシュの成立を保証しません。受け取ったFBXをアプリまたは作業用Blenderで読み込み、対象の形状、向き・単位、面構成、材質・UV・必要なテクスチャを確認します。外部テクスチャがある場合は参照先と画像も保存して呼び出し元へ渡します。出力がZIPだった場合はこのFBX用スクリプトへ渡さず、内容を確認して必要なFBXと画像を安全に展開し、別途検査します。

モデルID・用途・プリセット・保存先・サイズ・SHA256をworkの取得記録へ残し、呼び出し元の登録コマンドへ渡します。同じモデルでも書き出しごとにFBXのハッシュが変わり得るため、形状の比較には頂点・面・境界箱等も使います。取得だけの依頼では正本の採用状態を変更しません。

## 失敗した場合

ブラウザ・OS・操作ツールがExportや保存を明示的に拒否したら、同じ操作を繰り返さず、対象・形式・保存先・エラーを報告します。ツールの承認手順に従い、制限を回避する別セッションや認証情報の抽出へ切り替えません。待機タイムアウトだけなら、まず指定した実ファイルの有無とブラウザの表示を確認し、拒否と区別します。接続や保存設定に必要な対応を案内し、通常の復旧策としてユーザーの手動Exportを要求しません。ダウンロードのための再生成や追加の有料処理は行いません。

通常Exportは既存タブ、エージェントが追加したタブ、全タブを閉じた後に追加したタブで検証済みです。ダウンロード待ち機能との競合は有力な仮説ですが、根本原因が確定したとは扱いません。
